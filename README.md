# ПОС — преподавательская оценка студентов

Консольное приложение на C# для работы со студентами, рубрикатором, оценками и итоговой ведомостью.

## Запуск

~~~powershell
dotnet build POS.sln
dotnet test POS.sln
dotnet run --project src/POS.Console
~~~

## Предметная модель

| Термин | Объект | Ответственность |
|---|---|---|
| Студент | `Student`, корень агрегата | Хранит идентификатор, ФИО, год обучения, программу и группу. |
| ФИО, год обучения, балл | `FullName`, `StudyYear`, `Score` | Объекты-значения проверяют правила своих полей при создании. |
| Рубрикатор и критерий | `Rubric`, `Criterion` | Рубрикатор хранит критерии. У каждого критерия есть имя, максимальный балл и вес. Имя уникально внутри рубрикатора без учёта регистра, максимум и вес положительны. |
| Журнал и оценка | `Gradebook`, `Evaluation` | Журнал связывает студента с критерием текущего рубрикатора. На одну пару приходится одна оценка с баллом от нуля до максимума критерия включительно. |
| Итог | `FinalScoreCalculator` | Доменный сервис вычисляет итог по действующим критериям и выставленным оценкам. |

### Карточка студента

При добавлении студента программа сама выдаёт ему `StudentId` (GUID). Снимок данных проверяет, что этот идентификатор ещё свободен. Консоль может показать ID в списке, а поля для его ввода или изменения в карточке нет. Поэтому даже у двух студентов с одинаковым ФИО будут отдельные записи, а при смене имени, программы или группы оценки останутся у того же студента. Также это гарантирует уникальность ID.

Имя и фамилия обязательны, отчество можно оставить пустым. В каждом слове первая буква заглавная, остальные строчные. Поддерживаются русский алфавит с Ё/ё и английский алфавит, причём внутри одного слова буквы относятся к одному алфавиту. Между словами допускается один пробел или дефис, например в имени «Анна-Мария» или фамилии «Салтыков-Щедрин». Цифры, апострофы и другие знаки в ФИО отклоняются.

Год обучения — целое число от 1 до 6 в пределах текущей образовательной программы. Например, первый год магистратуры записывается как 1, даже если до этого студент четыре года учился в бакалавриате. Тот же принцип действует для аспирантуры. Верхняя граница 6 оставляет запас для программ длиннее стандартного четырёхлетнего бакалавриата. В карточке хранится текущая программа и год обучения в ней, который указывает пользователь. Программа и группа нужны для того, чтобы преподаветелю не пришлось искать каждого студента по ФИО. Обычно преподатели ведут либо у всей группы, либо лектор у всего потока, и для удобства можно просто написать все группы и сразу получить полный список. Также продумана возможность расширения, если преподаватель ведет курс по выбору и у него ребят из разных групп.

### Как считается итог

На шкале от 0 до 10 итог вычисляется по формуле `10 × Σ(вес × балл / максимум) / Σ(вес)`. Обе суммы учитывают критерии, по которым выставлены оценки. Ноль считается выставленной оценкой. Если оценки есть по части критериев, итог предварительный. Если оценок пока нет, числовое значение отсутствует.

Программа сохраняет рубрикатор и выставленные оценки в JSON, а итог вычисляет при просмотре или экспорте. Преподаватель может исправить оценку, изменить вес или максимальный балл критерия либо добавить новый критерий. При следующем запросе итог сразу будет рассчитан с учётом изменений. Для учебной ведомости достаточно вычислять результат по запросу, поэтому отдельная копия итогового балла в JSON не нужна. Экспортированный CSV отражает состояние на момент выгрузки.

При снижении максимума прикладной сервис ограничивает баллы, которые превышают новую границу, и сохраняет рубрикатор вместе с журналом за одну операцию. Перед удалением студента или критерия нужно отменить связанные оценки.

## Архитектура Ports and Adapters

Проект небольшой, сценариев и ожидаемых расширений немного. Здесь достаточно отделить правила оценивания от консольного ввода, хранения и экспорта. Ports and Adapters даёт для этого несколько понятных интерфейсов. Чтобы сменить способ хранения или добавить другой интерфейс, можно подключить новый адаптер через существующий порт. Дополнительные слои, отдельные репозитории для каждого агрегата и отдельные службы для такого объёма работы только усложнили бы проект. В силу своей простоты и понятности Ports and Adapters самая подходящая арзитектура.

| Проект | За что отвечает |
|---|---|
| `POS.Domain` | Правила модели. Здесь проверяются ФИО, диапазон балла и принадлежность критерия рубрикатору. Здесь же рассчитывается итог. |
| `POS.Application` | Сценарии работы со студентами, рубрикатором, оценками и ведомостью. `PosFacade` реализует входной порт `IPosOperations` и направляет команды профильным сервисам. Они используют выходные порты `IPosRepository` и `IResultExporter`. |
| `POS.Console` | Входной адаптер. Меню собирает ввод, вызывает прикладные сценарии и показывает результаты или ошибки. В `Program.cs` контейнер DI связывает порты с реализациями и регистрирует доступные стратегии округления. |
| `POS.Infrastructure` | Выходные адаптеры. `JsonPosRepository` читает JSON, восстанавливает доменные объекты с проверкой правил и сохраняет их. `CsvResultExporter` формирует ведомость с экранированием полей и кодировкой UTF-8 с BOM. |

`POS.Application` зависит от `POS.Domain`. Инфраструктура реализует интерфейсы приложения, а консоль вызывает его входной порт. Домен работает без консоли, форматов файлов и контейнера DI.

При выставлении оценки консоль передаёт команду через `IPosOperations`. Прикладной сервис загружает снимок через `IPosRepository`, находит студента и передаёт оценку в `Gradebook`. Журнал проверяет критерий, диапазон балла и отсутствие второй оценки по той же паре. После успешной проверки сервис сохраняет снимок через тот же порт.

Один JSON-файл содержит общий снимок студентов, рубрикатора и журнала. Так можно сохранить новый максимум критерия и изменённые оценки вместе. JSON-адаптер сначала записывает снимок во временный файл в той же папке, затем заменяет основной файл. Это решение рассчитано на последовательную работу одного экземпляра программы.

## Паттерны GoF

- **Builder.** помогает преподавателю собрать рубрикатор по шагам. Критерии можно добавлять по одному, просматривать в черновике и отменять последнее добавление. Это удобно, когда критериев несколько и хочется сначала увидеть их вместе, проверить веса и максимальные баллы. Если при добавлении допущена ошибка, уже введённые критерии остаются в черновике и настройку не приходится начинать заново. Рубрикатор сохраняется после подтверждения, когда преподаватель проверил весь список.
- **Facade.** позволяет держать консольное меню простым, даже когда за одним действием стоит несколько шагов. Например, чтобы выставить оценку, обработчик меню передаёт через `IPosOperations` выбранного студента, критерий и балл. `PosFacade` направляет запрос в сервис, который загружает данные, выполняет проверки и сохраняет изменение. Благодаря этому обработчики меню отвечают за ввод и показ результата, а порядок работы с данными описан в одном месте. Если сценарий выставления оценки изменится, его можно доработать в сервисе, сохранив тот же вызов из меню.
- **Strategy.** За округление итогового балла отвечает `IRoundingStrategy`, которую получает `FinalScoreCalculator`. Сейчас в меню доступны округление до ближайшего целого с половинами вверх и округление вниз. Правила могут уточняться из года в год. Например, учебный офис может попросить округлять значения ниже 4 строго вниз, а остальные — до ближайшего целого. Такую политику можно реализовать отдельной стратегией. Для выбора в консоли потребуется зарегистрировать её в `Program.cs` и добавить режим в меню. Формула итогового балла и модель критериев при этом остаются прежними.
